How to use this page

  1. Open the workshop folder as a project in RStudio.
  2. Work from the top. Read the explanation, press Copy, paste into the RStudio Console and press Enter.
  3. Wait until the Console shows the > prompt again before the next step. Tick Done to keep your place; your ticks are remembered in this browser.
  4. Run every step in order. Later steps use objects and files made by earlier ones.

If something fails, read the red message in the Console first, then see the common problems table in the beginner guide.

Read this before interpreting anything

The reads were selected because they match a bacterial reference panel, each comparison has three samples per condition, and one study group used a different identity threshold. Treat every result as exploratory: good for learning the method, not for biological conclusions.

Run mothur commands one by one

The idea. mothur is a separate program for processing 16S rRNA gene sequences. Here R starts one mothur session and sends it one command at a time, so you can read what each command prints before moving on.

Each command names its input files in full, so you can always see exactly which file goes in. After every command, get.current() lists the files mothur produced most recently; reading that list is the quickest way to check that a step did what you expected. A few blocks also check first that their input exists and that the step has not already been run, and stop with a clear message if not.

File names grow as you go. reads.trim.contigs.good.unique.fasta reads from left to right as a history: contigs were made, bad ones removed (good), duplicates collapsed (unique).

Assemble and screen reads

Goal of this stage. Turn each pair of raw reads into one clean sequence. The forward and reverse reads overlap in the middle of the amplicon; joining them gives a longer, more accurate sequence called a contig. Then sequences that are obviously faulty are discarded and identical sequences are collapsed so later steps run faster.

6

Set the number of processors set.current

mothur > set.current(processors=4)

Tells mothur how many processor cores it may use. More cores make the slow steps (alignment, distances) faster. Nothing is analysed yet.

R block that sends this command and waits for it
{
  if (!mothur_process$is_alive()) stop("The mothur session has closed. Run setup and the three session-start steps again.")
  mothur_command_start <- length(readLines(mothur_log, warn = FALSE))
  mothur_target <- sum(grepl("Current files saved by mothur:", readLines(mothur_log, warn = FALSE), fixed = TRUE)) + 1L
  cat("mothur > set.current(processors=4)\n")
  flush.console()
  mothur_process$write_input("set.current(processors=4)\nget.current()\n")
  repeat {
    mothur_output <- readLines(mothur_log, warn = FALSE)
    if (length(mothur_output) > mothur_cursor) {
      cat(paste(mothur_output[seq.int(mothur_cursor + 1L, length(mothur_output))], collapse = "\n"), "\n")
      flush.console()
      mothur_cursor <- length(mothur_output)
    }
    if (sum(grepl("Current files saved by mothur:", mothur_output, fixed = TRUE)) >= mothur_target) break
    if (!mothur_process$is_alive()) stop("Mothur stopped; check the output above")
    Sys.sleep(0.2)
  }
  if (any(grepl("[ERROR]", mothur_output[seq_along(mothur_output) > mothur_command_start], fixed = TRUE))) stop("Mothur reported an error; check the output above")
}

Check your understanding

Answer in your head first, then open to compare.

Why are the forward and reverse reads joined into one contig before anything else?

Each read covers only part of the amplicon and read quality drops towards its end. The two reads overlap, so joining them gives the full region and lets the better-quality base win wherever they disagree.

What is a chimera, and why does it matter if chimeras stay in the data?

A chimera is an artificial sequence made from two different templates during PCR. It looks like a new organism that does not exist, so leaving chimeras in inflates the number of OTUs and the diversity.

The OTU table and the ASV table are built from the same sequences. Why do they have different numbers of columns?

An OTU groups all sequences within 3% of each other, while every unique sequence is its own ASV. Several ASVs therefore usually fall into one OTU, so the ASV table has more columns.

MetaQC: can the studies be combined?

Why MetaQC. A meta-analysis only makes sense if the studies measure comparable things. MetaQC (Kang et al., Nucleic Acids Research 2012; R package by Don Kang and George Tseng) gives every study a score on six quality measures and so turns the decision to include or exclude a study into an objective rule. It was written for gene-expression studies; here the “genes” are OTUs and the “pathways” are taxonomic groups (phylum, class, order, family, genus).

  • IQC (internal quality control): is the co-abundance structure of the study (which OTUs rise and fall together) similar to that of the other studies? This is the homogeneity check.
  • EQC (external quality control): do OTUs of the same taxonomic group co-vary more than random OTUs?
  • CQCg / CQCp (consistency quality control): does the study rank OTUs (g) and taxonomic groups (p) by their C1-versus-C2 difference in the same order as the other studies combined?
  • AQCg / AQCp (accuracy quality control): does the study find the same significant OTUs or groups as the other studies combined?

How to read a score. Each score is −log10(p-value): higher is better. With K studies a score passes when it is above −log10(0.05/K), which is 2.0 for five studies. MetaQC marks scores below that line with an asterisk (*). The Rank column is the mean rank of a study over the six measures; lower is better.

The decision rule used here. IQC (homogeneity) and CQC (consistency) are the two measures that decide. A study is excluded when it fails both IQC and CQCg; all other studies go on to the diversity analyses, ANCOM-BC and the meta-analysis.

Keep in mind. MetaQC was designed for thousands of genes and larger groups. With 10 to 17 OTUs and three samples per condition, the consistency and accuracy measures (CQC, AQC) cannot reach significance in any study, so the decision rests mainly on IQC.

Adapt the IQC calculation to small tables.

MetaQC computes IQC by comparing the OTU-by-OTU correlations of every pair of studies. To save memory with thousands of genes it repeats this 100 times on a random 10% of the shared genes. With about ten shared OTUs, 10% is a single OTU and no correlation can be computed, so this function does the same comparison once on all shared OTUs. Everything else in MetaQC is used unchanged.

R code
iqc_all_shared <- function(.) {
  pairs <- combn(length(.$.DListF), 2)
  distance <- apply(pairs, 2, function(ii) {
    shared <- intersect(rownames(.$.DListF[[ii[1]]]$x), rownames(.$.DListF[[ii[2]]]$x))
    correlations <- sapply(1:2, function(j) as.vector(as.dist(cor(t(.$.DListF[[ii[j]]]$x[shared, , drop = FALSE])))))
    correlations <- na.omit(correlations)
    (1 - cor(correlations[, 1], correlations[, 2], method = "spearman")) / 2
  })
  m <- matrix(0, length(.$.DListF), length(.$.DListF), dimnames = list(names(.$.DListF), names(.$.DListF)))
  m[t(pairs)] <- distance
  m[t(pairs[2:1, ])] <- distance
  .$.DistOfStudies <- as.dist(m)
}

Alpha diversity: Observed, Chao1, Shannon and Inverse Simpson

What it measures. Diversity within one sample.

  • Observed: how many different OTUs are present (richness).
  • Chao1: an estimate of the true richness. It adds to the observed count an estimate of the OTUs that were missed, based on how many OTUs were seen only once or twice. If no OTU is seen only once, Chao1 equals Observed.
  • Shannon: richness and evenness together.
  • Inverse Simpson: the effective number of dominant OTUs; it gives more weight to the abundant ones.

Keep in mind. With three samples per condition, an exact two-sided test cannot give a p-value below 0.1.

exact_test <- function(x) {
  observed <- mean(x[4:6]) - mean(x[1:3])
  permuted <- apply(allocations, 2, function(i) mean(x[-i]) - mean(x[i]))
  c(difference = observed, p = mean(abs(permuted) >= abs(observed) - 1e-12))

Beta diversity: Bray–Curtis, Canberra, Jclass and ThetaYC

What it measures. How different two samples are from each other. Four distances are used, the same calculators that mothur offers in dist.shared:

  • Bray–Curtis: based on abundances; dominated by the common OTUs.
  • Canberra: based on abundances, but every OTU counts equally, so rare OTUs matter as much as common ones.
  • Jclass (Jaccard): uses only presence or absence. It answers “do the two samples contain the same OTUs?”
  • ThetaYC (Yue & Clayton): compares the community structure, that is the proportions of shared and unshared OTUs.

PCoA. Each distance matrix is turned into a map in which similar samples sit close together. The percentage on each axis is the share of the total variation that the axis shows.

PERMANOVA asks whether the condition explains part of the distances (R²). PERMDISP asks whether one condition is simply more spread out than the other, which can make PERMANOVA misleading. Both tests are exact here: with six samples vegan can try every possible reordering of the samples instead of a random selection. There are only 20 ways to split six samples into two groups of three, so the smallest possible PERMANOVA p-value is 1/20 = 0.05.

Write a function that returns the outline of an ellipse around the samples of one condition.

The ellipse is centred on the mean of the samples and follows their spread (their covariance); it covers about 68% of a normal distribution fitted to them. stat_ellipse() from ggplot2 needs at least four samples per group, so with three the ellipse is calculated here.

R code
ellipse_points <- function(points, level = 0.68) {
  xy <- as.matrix(points[, c("PCoA1", "PCoA2")])
  spread <- eigen(cov(xy), symmetric = TRUE)
  circle <- rbind(cos(seq(0, 2 * pi, length.out = 100)), sin(seq(0, 2 * pi, length.out = 100)))
  outline <- t(colMeans(xy) + spread$vectors %*% (sqrt(pmax(spread$values, 0) * qchisq(level, 2)) * circle))
  data.frame(condition = points$condition[1], PCoA1 = outline[, 1], PCoA2 = outline[, 2])
}

ANCOM-BC per study: effect size and standard error for every OTU

One study at a time. ANCOM-BC is run separately in each included study, never on a merged table, so that differences between studies (sequencing depth, filtering) cannot create false differences between conditions. From every study we keep, for each OTU, the effect size (log fold change) and its standard error (SE): exactly the two numbers the meta-analysis needs.

Why ANCOM-BC instead of LEfSe. LEfSe first needs a Kruskal–Wallis p-value below 0.05. With three samples per condition the smallest value that test can give is 0.0495, and after adjustment for multiple testing nothing passes, so LEfSe reported no OTU in any study whatever the LDA cut-off. LEfSe also gives a score without a standard error, which a meta-analysis cannot use.

What ANCOM-BC does. Sequencing gives relative abundances: if one OTU goes up, the others must appear to go down even if they did not change. ANCOM-BC estimates and removes this bias, then reports for each OTU its effect size, the log fold change between conditions, together with a standard error, a p-value and an adjusted p-value (q). The function used is ancombc2(), the current version in the ANCOMBC package; the reference paper also used ANCOM-BC.

How to read a value. A log fold change of 0 means no difference; +0.69 means about twice as abundant in C2; −0.69 means about half.

Random-effects meta-analysis (metafor, REML) for every OTU

The idea. Each study is small, but there are several of them. ANCOM-BC gave, for each OTU in each study, an effect size (log fold change) and its standard error. A meta-analysis combines the study estimates of one OTU into one pooled effect size. It has two parts: a check of which estimates can be pooled, and the random-effects model (REM), fitted with metafor::rma(method = "REML"), which does the pooling.

This is a different check from MetaQC at the start of the chapter: MetaQC decided which studies are combined; this step decides which estimates of those studies can be used.

Part 1: which estimates can be pooled. A pooled result is only as good as what goes into it, so three checks come first.

  • Is each estimate usable? An estimate is kept only if ANCOM-BC could really test the OTU in that study: it has a log fold change, a standard error and a p-value. OTUs found in only one condition, or in a single sample of each condition, are left out.
  • Are there enough studies? An OTU is pooled only if at least three studies have a usable estimate. With one or two studies there is nothing to compare.
  • Are the studies comparable? MetaQC has already removed the study that was not homogeneous with the others. The remaining studies were processed with the same mothur pipeline and the same reference, so their OTUs mean the same thing. They still differ in read depth (see the first figure of this chapter) and in one filtering threshold (G5 used 97% identity). These differences are a reason to prefer a random-effects model and to check each result with one study left out.

Part 2: the random-effects model (REM). A fixed-effect model assumes that all studies measure exactly the same true effect and differ only by chance. A random-effects model is more realistic here: it assumes that each study has its own true effect, and that these true effects scatter around an average. That average is the pooled effect size.

  • Each study estimate = average effect + how far this study’s true effect is from the average + sampling error.
  • tau² is the variance of the true effects between studies. If tau² is 0 the random-effects model gives the same answer as the fixed-effect model.
  • REML. tau² is estimated by restricted maximum likelihood (method = "REML"), the default in metafor. With few studies, plain maximum likelihood underestimates tau²; REML corrects for that.
  • Each study gets the weight 1 / (standard error² + tau²). Precise studies count more, but a large tau² makes the weights more equal, so no single study dominates.
  • estimate is the weighted average of the study effect sizes, with a 95% confidence interval. An interval that includes 0 is compatible with no difference.
  • I² is the percentage of the total variation that comes from real differences between studies and not from chance; the Q test asks whether there is more variation than chance alone would give. These two are the quality control of the pooled result itself.

Two OTUs are first worked through by hand so that you can see every step. Then one function repeats exactly the same steps for all OTUs.

What a cladogram shows. The taxonomy drawn as a tree: the inner ring is the kingdom, each step outwards is a lower rank (phylum, class, order, family, genus), and the outer nodes are the OTUs. Every OTU is labelled with its number and genus, and the phylum (bold) and family are written on the inner nodes.

One tree, all included studies, two conditions. All OTUs that ANCOM-BC analysed are in one tree. Outside the tree there is one ring of tiles per included study (G1 innermost). A tile is salmon when the OTU is higher in C1 in that study and teal when it is higher in C2; it is strongly coloured when the difference is significant and pale when it is not, and it is missing when the study has no usable estimate. The tree nodes show the pooled result of the included studies: salmon or teal when the pooled effect is significant, olive when it is not. A shaded sector marks each significant OTU.

Effect size of alpha diversity across the included studies

The idea. The same random-effects model is applied to alpha diversity. For each index and study the effect size is the mean difference, C2 minus C1; its variance comes from the spread within each condition. The quality-control rule here is that a study needs a variance above 0 to be weighted.

Keep in mind. One study group was filtered at 97% identity and the others at 99%. Differences between studies may therefore reflect filtering as well as biology.

Check your understanding

What does a low IQC score tell you about a study?

That its co-abundance structure (which OTUs rise and fall together) differs from that of the other studies more than they differ from each other. Combining such a study with the others mixes different things, which is why MetaQC excluded G4.

Why can no study pass CQC or AQC here, and is that a reason to exclude all of them?

Consistency and accuracy need a clear C1-versus-C2 signal in each study, and three samples per condition cannot give one. It is a limit of the data, not of the studies, so the decision rests on IQC, which does not depend on the condition labels.

Why is ANCOM-BC run separately in each study instead of on one merged table?

Studies differ in sequencing depth, filtering and population. On a merged table those differences can look like differences between conditions. Run per study, each estimate compares C1 and C2 within the same study, and the meta-analysis then combines the estimates.

Why was LEfSe replaced by ANCOM-BC?

With three samples per condition LEfSe’s first test cannot pass after adjustment, so it reports nothing. ANCOM-BC corrects for compositional bias and gives every OTU an effect size with a standard error, which is exactly what a meta-analysis needs.

What is the difference between a fixed-effect and a random-effects model, and what does REML do?

A fixed-effect model assumes every study measures the same true effect. A random-effects model lets the true effect differ between studies and estimates how much (tau²). REML is the method used to estimate tau²; with few studies it is less biased than plain maximum likelihood.

Otu16 is not significant in any single study, but it is in the pooled analysis. How is that possible?

Each study alone is too small to give a precise estimate. All three estimates point the same way, and combining them gives a narrower confidence interval than any single study has.

One study group was filtered at 97% identity. Why does that matter for the pooled results?

A looser threshold keeps different reads, so a difference between G5 and the other studies may come from the filtering and not from biology. In the forest plot of Otu05, G5 is the one study that points the other way, and leaving it out makes the pooled effect significant.

Glossary

16S rRNA gene
A gene found in all bacteria. Parts of it are nearly identical everywhere (good for primers) and parts vary between groups (good for telling bacteria apart).
Read pair
Two sequences read from opposite ends of the same DNA fragment: forward (R1) and reverse (R2).
Contig
One sequence made by joining an overlapping forward and reverse read.
FASTA / FASTQ
Text formats for sequences. FASTQ also stores a quality score for every base.
Count table
mothur file recording how many times each unique sequence occurs in each sample.
Chimera
An artificial sequence made of two different templates during PCR.
OTU
Operational taxonomic unit: a cluster of sequences that are at least 97% similar.
ASV
Amplicon sequence variant: one exact unique sequence treated as a feature.
Phylotype
A group of sequences that share the same taxonomic name.
Shared file
mothur's feature table: one row per sample, one column per OTU, ASV or phylotype.
Relative abundance
A feature's count divided by the sample's total, so samples of different depth can be compared.
Subsampling (rarefying)
Randomly drawing the same number of reads from every sample to equalise depth.
Alpha diversity
Diversity within one sample (observed OTUs, Shannon, inverse Simpson).
Beta diversity
Difference in composition between two samples (for example Bray–Curtis).
PCoA
Principal coordinates analysis: a map of samples in which map distance approximates dissimilarity.
PERMANOVA
A permutation test of whether groups of samples differ in composition, based on a distance matrix.
Chao1
An estimate of the true number of OTUs in a sample, including those that were probably missed, based on the OTUs seen only once or twice.
Bray–Curtis
A distance between two samples based on OTU abundances; dominated by the common OTUs.
Canberra
A distance based on abundances in which every OTU has the same weight, so rare OTUs matter.
Jclass
The Jaccard distance on presence or absence: the share of OTUs that the two samples do not have in common.
ThetaYC
The Yue & Clayton distance, which compares community structure using the proportions of all OTUs.
PERMDISP
A permutation test of whether the samples of one group are more spread out than those of another.
MetaQC
An R package that scores each study of a meta-analysis on six quality measures (IQC, EQC, CQCg, CQCp, AQCg, AQCp) to decide objectively which studies can be combined.
IQC
Internal quality control: whether a study has the same co-abundance structure as the other studies (homogeneity).
CQC
Consistency quality control: whether a study ranks features (CQCg) or groups (CQCp) by their difference between conditions in the same order as the other studies combined.
REML
Restricted maximum likelihood, the method metafor uses by default to estimate the between-study variance tau².
ANCOM-BC
A differential-abundance method that corrects for the bias of compositional data and reports a log fold change with a standard error for each feature.
Effect size
How large a difference is, as opposed to how certain it is. Here: the log fold change of an OTU, or the C2-minus-C1 difference of a diversity index.
Log fold change
The natural logarithm of the ratio between two abundances. 0 means equal; 0.69 means twice as much.
Forest plot
A figure showing the estimate and confidence interval of each study and the pooled estimate underneath.
Cladogram
A tree drawing of the taxonomy, used here to show where the differing OTUs sit.
p-value adjustment (BH)
The Benjamini–Hochberg correction, which limits false discoveries when many tests are run.
Random-effects meta-analysis
Pooling of estimates from several studies while allowing the true effect to vary between them.
Exploratory
Useful for learning and for generating ideas, but not strong enough to support a firm conclusion.
